# Smart City Traffic Management and Route Optimization System

A decision-support tool that models a city's road network as a weighted graph and uses graph
algorithms to help **commuters** pick routes and **city administrators** manage traffic and plan roads.

**DAA Lab 4 Capstone** - Bulbul, Roll No. 2401201214, BCA (AI & Data Science), Section A, K.R. Mangalam University.

> The city in `data/` is **synthetic** (32 junctions, 51 roads, generated by `scripts/generate_city.py`).
> No real traffic data is used.

## What it does

| Feature | Algorithm(s) |
|---|---|
| Fastest / shortest route, turn-by-turn | Dijkstra, A*, Bellman-Ford (selectable, all give the same optimal cost) |
| Alternative routes | Penalty method on top of Dijkstra |
| Reachability, "what can I reach in N hops", cut-off zones | BFS, DFS, connected components |
| Cheapest road backbone for infrastructure planning | Kruskal and Prim (MST) |
| Critical roads whose closure splits the city | Bridge finding (Tarjan low-link) |
| Traffic: travel time grows with congestion | BPR function `t = t0 * (1 + 0.15 * (v/c)^4)` |
| Closures and incidents, impact on trips | Re-routing with closed edges |
| Performance analysis on 100 to 4000 junctions | Timing of every algorithm |

All algorithms are written from scratch in `smartcity/graph.py`. `networkx` is used **only in the tests**
as an independent check.

## Run it

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py                                   # opens http://localhost:8501
```

Run the tests (compares every algorithm with networkx on the sample city and on random graphs):

```bash
python -m pytest -q tests
```

Other scripts:

```bash
python scripts/generate_city.py        # regenerate data/nodes.csv and data/roads.csv
python -m smartcity.benchmark          # re-run the benchmark -> docs/benchmark_results.json
python scripts/build_report.py         # rebuild the capstone PDF (needs the app running for screenshots)
```

## Project layout

```

smartcity/viz.py        Plotly network map
smartcity/benchmark.py  Random city generator + timing

docs/                   screenshots, benchmark_results.json, capstone report

```

## Data format

`data/nodes.csv`: `id, name, x_km, y_km, kind`
`data/roads.csv`: `id, from, to, distance_km, speed_limit_kmh, capacity_vph, base_volume_vph, road_type, build_cost_per_km`

Replace these two files with your own city and the app picks them up (coordinates should be in km, and
`distance_km` should be at least the straight-line distance so A* stays optimal).

## Limitations

- Synthetic data and a static traffic snapshot per time period (no live feed).
- Alternative routes use the penalty method, which is simple but not guaranteed to be the k best routes.
- Roads are two-way; one-way streets and turn restrictions are not modelled.
